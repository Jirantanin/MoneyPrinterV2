# Claude ไม่ได้เสกวิดีโอ แต่เขียนโค้ดวาดทุกเฟรม

จริงแค่ครึ่งเดียว Claude ทำวิดีโอแนว motion graphics ได้สวยขึ้นจริงตั้งแต่ **Claude Opus 5.5 เปิดตัวเมื่อ 22 ก.ย. 2026** แต่ตัวโมเดลไม่ได้สร้างพิกเซลวิดีโอออกมาเลยสักเฟรม โมเดลปัจจุบันทุกตัว **รับ text กับภาพนิ่ง แล้วตอบเป็น text อย่างเดียว** ([Claude Docs: Models overview](https://platform.claude.com/docs/en/about-claude/models/overview)) คลิปที่แชร์กันว่อน X คือ Claude เขียนโค้ดวาดทีละเฟรม แล้วสั่ง headless browser กับ ffmpeg (หรือ Remotion และ HyperFrames) อัดออกมาเป็น MP4 วลี "ไม่ต้องต่ออะไร" จึงถูกเฉพาะในแง่ที่ไม่ต้องพึ่ง video model หรือ MCP สำหรับกราฟิกที่โค้ดวาดได้ ตัวงานยังต้องมีที่รันโค้ดอยู่ดี จะเป็น Claude Code บนเครื่องหรือ sandbox ของ claude.ai/Cowork ก็ตาม ส่วนเสียงพากย์ เพลง และภาพจริง ยังต้องมาจากไฟล์ที่มีอยู่แล้วหรือบริการภายนอกทั้งหมด และ Anthropic เองก็ไม่เคยประกาศฟีเจอร์วิดีโอเลยสักตัว คุณภาพจริงแบ่งได้สองชั้น คลิปสั้นที่ "เรนเดอร์ผ่าน" แทบไม่พลาดแล้ว แต่คลิปที่ "ดี" ยังต้องวนแก้หลายรอบและต้องมีคนกำกับภาพ ปัญหาที่เจอซ้ำคือหน้าตาจืดจนดูออกว่าเป็นงาน AI วางองค์ประกอบชนกัน จังหวะเร็วจนอ่านไม่ทัน และบทลื่นแต่ตื้น สำหรับช่องสารคดีไทยที่รัน Claude Code กับ renderer ของตัวเองและ Gemini TTS อยู่แล้ว กระแสนี้ไม่ได้เปิดทางใหม่ แต่ยืนยันว่าทางที่เดินอยู่แข็งแรงที่สุดในบรรดาทางที่มี ความเสี่ยงจริงไม่ได้อยู่ที่ฝีมือทำวิดีโอ แต่อยู่ที่ว่างานจะดูเป็น template ในสายตา YouTube หรือเปล่า

## คลื่นไวรัลมาหลัง Opus 5.5 แต่ประกาศทางการไม่มีคำว่าวิดีโอสักบรรทัด

กระแสนี้เริ่มบน X ช่วง **22–28 ก.ย. 2026** ภายในสัปดาห์เดียวหลัง Opus 5.5 ออก OfficeChai รวบรวมตัวอย่างดังไว้สิบชิ้น มีทั้งคลิปประวัติศาสตร์ AI ยาวราว 3 นาทีของ @kimmonismus ที่ยืนยันว่าทุกเฟรม "เรนเดอร์จากโค้ด" ไม่ใช้ stock footage และไม่ใช้ image หรือ video generator, demo reel แนว motion designer ที่ทำจาก prompt ประโยคเดียวในราว 15 นาที และคลิปประวัติศาสตร์อารยธรรมตะวันตกของ @IterIntellectus ที่ OfficeChai บอกว่า Elon Musk กับ Marc Andreessen แชร์ต่อจนยอดแชร์เกิน 12,000 ครั้ง ([OfficeChai](https://officechai.com/ai/claude-opus-5-5-motion-graphic-videos/)) โพสต์สาย "ไม่ใช้ generator เลย" แบบนี้แหละที่น่าจะกลายมาเป็นวลี "ไม่ต้องต่ออะไร" แต่บทความเดียวกันก็เขียนไว้ว่าโมเดลทำงานจบได้ "เมื่อได้เครื่องมือที่ใช่" และชิ้นที่ดูเป็นหนังที่สุดในลิสต์ คือสารคดีสไตล์ Netflix เรื่อง superintelligence ของ @gavinpurcell ก็ **ต่อ Runway MCP ไว้ด้วย**

พอเปิดดูเบื้องหลังทีละชิ้น คำว่า "one-shot" ก็เริ่มเกินจริง มิวสิกวิดีโอของ "donald" ใช้ Opus 5.5 รันราว **12 ชั่วโมง** กับ prompt ยาวเกือบ 10,000 ตัวอักษรที่ใส่ทั้ง skills ตัวอย่างงาน และ **API key** ไว้ข้างใน ส่วนเวอร์ชันของ @anabology ที่ Musk ชมหนักสุดก็เติม asset จาก Midjourney เข้าไป BestHub สรุปห้วนๆ ว่า "One-click finished video? Dream on." ([BestHub](https://www.besthub.dev/articles/opus-5-5-codes-music-videos-musk-retweets-prompt-engineering-sonnet-5-5-leak-a562393c62a6)) โปรเจกต์ PDoomVideo มิวสิกวิดีโอยาว 156.6 วินาที ต้องทำใน Claude Code สองรอบ ให้ sub-agent เขียนตัววาด p5.js แยกตามบท แล้วใช้ Node สั่ง headless Chrome จับภาพราว 3,760 เฟรมที่ 24 fps ก่อนให้ ffmpeg รวมกับไฟล์เพลงที่มีอยู่แล้ว ([OrcaRouter TH](https://www.orcarouter.ai/th/blog/claude-opus-5-5-video-plan-one-shot)) ในกระทู้ Hacker News ก็มีคนชี้ว่าคลิปที่ถูกอ้างว่าเป็น "Opus 5.5 ล้วน" บางชิ้นใช้ภาพจาก image model ที่ Claude สั่งผ่าน OpenRouter ([HN 49836374](https://news.ycombinator.com/item?id=49836374)) หลายชิ้นที่บอกว่า "Claude ทำ" จริงๆ แล้วคือ "Claude คุมงาน" ต่างหาก

ฝั่ง Anthropic เงียบกว่าที่กระแสพาไป หน้าประกาศ Opus 5.5 ไม่พูดถึงวิดีโอ แอนิเมชัน หรือ motion graphics เลย ([Anthropic: Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)) release notes ตั้งแต่ เม.ย. ถึง ต.ค. 2026 ก็ไม่มีรายการไหนเอ่ยถึง video, MP4, GIF หรือ animation ([Claude Help Center: Release notes](https://support.claude.com/en/articles/12138966-release-notes)) เอกสาร Vision เขียนตรงๆ ว่า Claude เป็นโมเดลที่เข้าใจภาพอย่างเดียว สร้างหรือแก้ภาพไม่ได้ ([Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)) Cybernews ยังรายงานเคสคนจ่ายราว $7 ให้ Opus 5.5 ทำภาพ "วัววิ่ง" แล้วได้วัวที่วิ่งด้วยเต้านม พร้อมสรุปว่าโมเดลนี้ไม่ได้ออกแบบมาเพื่องานแอนิเมชัน วิดีโอ หรือสร้างภาพ ([Cybernews](https://cybernews.com/ai-news/claude-opus-running-cow/))

ของที่ Anthropic ปล่อยจริงเป็นตัวช่วยรอบข้างมากกว่า Claude Design เปิดตัวเป็น research preview เมื่อ 17 เม.ย. 2026 ใช้สร้าง prototype ที่ขับด้วยโค้ด ใส่ voice, video, shaders และ 3D ได้ ([Anthropic: Claude Design](https://www.anthropic.com/news/claude-design-anthropic-labs)) จากนั้น **16 ก.ย. 2026** ก็มีสองเรื่องออกพร้อมกัน Design, Slides และ Docs ใช้ได้ในทุกบทสนทนาทุกแผนรวมถึง Free ส่วน Cowork เริ่มทยอยเข้ามาอยู่ในทุกบทสนทนาของ Pro และ Max ([Claude Help Center: Release notes](https://support.claude.com/en/articles/12138966-release-notes)) อีกหกวันต่อมา Opus 5.5 ก็ออก คนที่ใช้ claude.ai เฉยๆ เลยสั่งงานที่รันโค้ดได้โดยไม่ต้องลงอะไรบนเครื่อง ตรงนี้น่าจะเป็นฐานจริงของความรู้สึก "ไม่ต้องต่ออะไร" แม้ไม่มีอันไหนถูกประกาศเป็นฟีเจอร์วิดีโอเลยก็ตาม

ความเชื่อนี้ก็ไม่ได้ใหม่ทั้งหมด ต้นปี 2026 เคยมีกระแส "Claude Code + skill เดียวทำวิดีโอได้" มาแล้วรอบหนึ่ง โพสต์ที่เก่าที่สุดที่เจอเป็นบล็อกจีนเมื่อ 26 ม.ค. ที่ใช้ Remotion skill ทำคลิปจัดอันดับ ([heyuan110](https://www.heyuan110.com/posts/ai/2026-01-26-claude-code-remotion-video/)) ตามมาด้วย Remotion Agent Skills ทางการ ([Remotion docs: AI skills](https://www.remotion.dev/docs/ai/skills)) และ HyperFrames ของ HeyGen ที่เปิดซอร์สราว เม.ย. ([The Menon Lab](https://themenonlab.blog/blog/heygen-hyperframes-video-as-code)) ทั้งหมดต้องลง Node และ ffmpeg บนเครื่อง ฝั่งสื่อไทย บทความสอนตัดต่อของ Marketing Oops! เมื่อ 19 พ.ค. 2026 ใช้ Claude Desktop โหมด Code คู่กับ skill HyperFrames และ video-use แถมต้องมี **ElevenLabs API key** ไว้ถอดเสียงไทย คลิป HD ยาวหนึ่งนาทีใช้เวลาราว 10 นาทีและกินโควตาราว 25% ([Marketing Oops!](https://www.marketingoops.com/?p=364774)) ห่างจาก "ไม่ต้องต่ออะไร" ไปไกล ล่าสุดยังมีคลิป "Claude Next Model" ที่โพสต์เมื่อ 11 ต.ค. อ้างว่ากำลังเทสใน Claude Code แต่ Anthropic ไม่ได้ยืนยันอะไร และคลิปนั้นก็ใช้ภาพกับเพลงที่เตรียมไว้ก่อนแล้ว ([OrcaRouter TH](https://www.orcarouter.ai/th/blog/claude-next-video-code-leak))

## ไม่ลงอะไรเลยได้แค่ GIF กับคลิปสั้น วิดีโอเต็มเรื่องยังต้องพึ่ง Claude Code

ช่องทางที่ไม่ต้องต่ออะไรจริงๆ คือ sandbox ของ claude.ai ซึ่งรันโค้ดและสร้างไฟล์ได้ **ทุกแผนรวมถึง Free** ทั้งบนเว็บ desktop และมือถือ ([Help Center: Create and edit files with Claude](https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude)) แต่ไฟล์ที่เอกสารรับรองมีแค่ xlsx, pptx, docx, PDF, PNG และ artifacts ไม่มีวิดีโอหรือเสียงเลย มีแค่ FAQ ที่เอ่ยถึง "gif-creation" ไว้ประโยคเดียว **GIF จึงเป็นทางเดียวที่ยืนยันได้ว่าไม่ต้องตั้งค่าอะไร** skill `slack-gif-creator` ของ Anthropic เองก็วาดเฟรมด้วย Pillow โดยไม่แตะ ffmpeg ([anthropics/skills](https://raw.githubusercontent.com/anthropics/skills/main/skills/slack-gif-creator/SKILL.md))

MP4 ใน claude.ai ยังไม่มีใครยืนยัน Anthropic ไม่เคยบอกว่า sandbox มี ffmpeg ติดมาหรือไม่ Simon Willison สำรวจไว้เมื่อ ก.ย. 2025 เจอ Ubuntu 24.04 RAM ราว 9GB disk ราว 4.9GB พร้อม Python 3.12 และ Node 18 แต่ไม่ได้พูดถึง ffmpeg ([Simon Willison](https://simonwillison.net/2025/Sep/9/claude-code-interpreter)) และข้อมูลชุดนี้ก็เก่ากว่าหนึ่งปีแล้ว ทางที่น่าจะไปได้คือให้ Claude ลง encoder เอง เพราะแผน Free/Pro/Max เปิด network ไปยัง PyPI, npm, Ubuntu archives และ GitHub เป็นค่าเริ่มต้น ส่วน Enterprise ปิดไว้ก่อน ([Help Center](https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude)) แต่ข้อนี้อนุมานจาก allowlist ยังไม่เจอใครลองจริง เพดานที่ชัดกว่าคือ **ไฟล์ละไม่เกิน 30MB** ทั้งขาเข้าและขาออก ([Help Center](https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude)) คิดคร่าวๆ ที่ 1080p H.264 ราว 5 Mbps ก็เต็มเพดานในราว 48 วินาที claude.ai จึงเป็นพื้นที่ของคลิปสั้นเท่านั้น อีกสองจุดที่ไม่มีเอกสารเลยคือฟอนต์ไทย ถ้า sandbox ไม่มี ข้อความไทยที่วาดด้วย Pillow จะกลายเป็นกล่องสี่เหลี่ยม และ Playwright/Puppeteer ที่ต้องโหลด browser จาก CDN นอก allowlist ก็น่าจะอัด HTML เป็นวิดีโอใน sandbox ไม่ได้ (สองข้อหลังเป็นการอนุมาน ยังไม่มีใครทดสอบ) Daria Cupareanu ครีเอเตอร์ที่ทำคลิปชุดนี้เองเล่าว่าตัวอย่างส่วนใหญ่ในเน็ตทำใน Claude Code ตัวเธอใช้ Cowork มากกว่าครึ่ง แชต claude.ai ธรรมดาอาจ timeout ตอนเรนเดอร์นาน และเสียงพากย์กับเพลงในงานเธอก็มาจาก connector แบบเสียเงินที่มี Gemini TTS, ElevenLabs และ Veo อยู่ข้างหลัง ([AI Blew My Mind](https://aiblewmymind.substack.com/p/claude-opus-5-5-video-animations))

Artifact เล่นแอนิเมชัน HTML, canvas หรือ SVG ในหน้าเว็บได้ทันที แต่ผลลัพธ์คือหน้าเว็บ ไม่ใช่ไฟล์วิดีโอ และไม่มีปุ่ม export เป็น MP4 ทางเลี่ยงคือเขียนโค้ดใน artifact ให้ใช้ `canvas.captureStream()` คู่กับ `MediaRecorder` อัดออกมาเป็น WebM วิธีนี้ได้ไฟล์ก็ต่อเมื่อ iframe ยอมให้ดาวน์โหลด อัดแบบ real-time ตามความเร็วเครื่องคนดู และไฟล์มักไม่มี metadata ความยาว ([Theodo](https://blog.theodo.com/2023/03/saving-canvas-animations)) Claude Design ก็คลุมเครือพอกัน หน้าช่วยเหลือทางการระบุ export เป็น .zip, PDF, PPTX, Google Slides, HTML และส่งต่อให้ Claude Code ไม่มีวิดีโอในรายการ ([Get started with Claude Design](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)) ขณะที่ tutorial ของ xray.tech บอกว่าเมนู Share มีตัวเลือก "Video (.mp4)" ([xray.tech](https://www.xray.tech/post/build-fluid-on-brand-animations-with-claude-design)) แต่รีวิวของ Flowstep บอกว่า export เป็นวิดีโอไม่ได้ ต้องอัดหน้าจอเอา ([Flowstep](https://flowstep.ai/blog/claude-design-review/)) เรื่องนี้ต้องเปิดแอปเช็กเองถึงจะรู้ ที่น่าสังเกตคือหน้าทางการมี **Hyperframes** อยู่ในรายการ "Send to" ทางไปสู่ไฟล์วิดีโอที่ Anthropic เปิดไว้จึงอาจเป็น renderer ของคนอื่นมากกว่า export ของตัวเอง

นักพัฒนาที่หวังจะได้ MP4 กลับมาจาก API ล้วนๆ จะเจอ sandbox ที่ล็อกแน่นกว่า claude.ai อีก container ของ code execution tool มี RAM 5GiB, CPU เดียว, **ปิดอินเทอร์เน็ตทั้งหมด** และลง package เพิ่มระหว่างรันไม่ได้ library ที่ติดมามี matplotlib กับ pillow แต่ไม่มี ffmpeg, moviepy หรือ TTS ใดๆ ในรายการ ([Claude Docs: Code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)) ไฟล์ที่เขียนลง `$OUTPUT_DIR` กลับมาเป็น `file_id` ให้โหลดผ่าน Files API ได้ GIF จาก matplotlib หรือ WAV จาก numpy จึงได้แน่ แต่ MP4 ไม่น่าได้ เอกสารที่บอกว่าไฟล์ MP4 จาก sandbox จะติด C2PA Content Credentials บอกแค่ว่าถ้าสร้างได้จะถูกเซ็น ไม่ได้บอกว่ามี encoder ให้ใช้ ในทางปฏิบัติจึงต้องให้ Claude เขียนโค้ด composition แล้วไปเรนเดอร์บน server ของตัวเองแทน

ทางที่มีหลักฐานมากที่สุดและเป็นที่มาของคลิปไวรัลเกือบทั้งหมดคือ **Claude Code บนเครื่องตัวเอง** Claude เขียน React สำหรับ Remotion, HTML+GSAP สำหรับ HyperFrames, Python สำหรับ Manim หรือคำสั่ง ffmpeg ตรงๆ แล้วรัน renderer บนเครื่องผู้ใช้ Remotion มี Agent Skills ทางการที่ติดตั้งด้วย `npx skills add remotion-dev/skills` ([Remotion docs: AI skills](https://www.remotion.dev/docs/ai/skills)) ตั้งแต่ v4 ก็ฝัง ffmpeg มาให้ ([Remotion v4.0 migration](https://www.remotion.dev/docs/4-0-migration)) และลง Chrome Headless Shell ให้อัตโนมัติ ([Remotion: Chrome Headless Shell](https://www.remotion.dev/docs/miscellaneous/chrome-headless-shell)) HyperFrames ใช้ license Apache-2.0 ต้องมี Node 22 ขึ้นไปกับ FFmpeg ([Noqta](https://www.noqta.tn/en/blog/heygen-hyperframes-html-to-mp4-ai-agent-video-2026)) ส่วน Manim ตั้งแต่ 0.19.0 เปลี่ยนไปใช้ PyAV ที่มี FFmpeg ในตัวแล้ว ([Manim 0.19.0 changelog](https://docs.manim.community/en/stable/changelog/0.19.0-changelog.html)) จุดที่ต้องระวังคือ license ของ Remotion ใช้ฟรีได้เฉพาะบุคคล องค์กรไม่แสวงกำไร หรือบริษัทที่มี **พนักงานไม่เกิน 3 คน** นอกนั้นต้องซื้อ Company License ([Remotion LICENSE.md](https://raw.githubusercontent.com/remotion-dev/remotion/main/LICENSE.md))

ถ้าไม่อยากลงอะไรแต่ยอมต่อบริการภายนอก claude.ai ก็มี connector สายวิดีโอหลายตัวแล้ว HyperFrames by HeyGen อยู่ใน connector directory ตั้งแต่ มิ.ย. 2026 ติดป้าย "Anthropic verified" มี tool `compose` กับ `render_video` ([Claude Connectors: HyperFrames](https://claude.com/connectors/hyperframes-heygen)) connector ของ HeyGen ต่อผ่าน OAuth ทำ avatar พร้อม lip-sync หลายภาษา และหักจากเครดิตในบัญชี HeyGen ([HeyGen x Claude](https://www.heygen.com/integrations/claude)) Higgsfield ต่อเป็น custom connector เพื่อเรียก video model หลายสิบตัวตามที่ vendor อ้าง ([Higgsfield](https://higgsfield.ai/claude-ai-video-generator)) ทั้งหมดนี้คือการ "ต่อ" ตามความหมายตรงตัว และเสียเงินตามเครดิตด้วย

| ช่องทาง | ได้อะไรออกมา | ต้องต่อหรือติดตั้งอะไร | สถานะหลักฐาน |
|---|---|---|---|
| claude.ai sandbox วาดเฟรมด้วย Pillow/matplotlib | GIF ไม่เกิน 30MB | ไม่ต้อง | ยืนยันแล้ว (FAQ และ skill ของ Anthropic) |
| claude.ai sandbox + ffmpeg | MP4 ไม่เกิน 30MB | น่าจะไม่ต้องบน Free/Pro/Max เพราะ Claude ลงเองได้ | ยังไม่มีใครทดสอบ อาจใช้ไม่ได้บน Team/Enterprise |
| Artifact (HTML/canvas/SVG) | หน้าเว็บที่เล่นแอนิเมชัน ไม่ใช่ไฟล์ | ไม่ต้อง | ยืนยันแล้ว |
| Artifact + MediaRecorder | WebM ที่อัดแบบ real-time | ไม่ต้อง ถ้า iframe ยอมให้ดาวน์โหลด | ยังไม่ยืนยัน |
| Claude Design | MP4 (มีหรือไม่มี ยังเถียงกันอยู่) | ไม่ต้อง | เอกสารทางการไม่มี แหล่งรองขัดกัน |
| API code execution | GIF/WAV ผ่าน Files API | ไม่ต้อง | MP4 ไม่น่าได้ (ไม่มี ffmpeg ไม่มี network) |
| Claude Code + Remotion/HyperFrames/Manim/ffmpeg | MP4 ยาวเท่าไหร่ก็ได้ ใส่เสียงที่หามาเองได้ | ลง toolchain บนเครื่อง | ทางหลัก หลักฐานมากที่สุด |
| claude.ai + connector (HyperFrames, HeyGen, Higgsfield, Runway) | วิดีโอที่เรนเดอร์บนบริการภายนอก | บัญชีและเครดิตของบริการนั้น | มีหน้า connector ทางการ บางตัวเป็นข้อมูลจาก vendor |

## เรนเดอร์ผ่าน 17 จาก 17 ครั้ง แต่ยังไม่มีใครวัดว่าสวยหรือเปล่า

การทดสอบที่มีโครงสร้างที่สุดตอนนี้มาจาก agentskillshub เมื่อ 11 ต.ค. 2026 ให้ Claude Code บน Opus 5.5 ทำคลิปโปรโมต 15 วินาที 1920×1080 ที่ 30 fps พร้อมข้อความห้าบรรทัดชุดเดียวกัน ด้วย Remotion skill 16 ตัวกับรอบที่ไม่ใช้ skill อีกหนึ่งรอบ ผลคือ **ผ่านครบทั้ง 17 รอบ** ไฟล์เล่นได้ ความยาวกับขนาดถูก ข้อความทุกบรรทัดอ่านออกในเฟรมที่สุ่มดูวินาทีละสองครั้ง และภาพขยับจริง เวลาทำเสร็จอยู่ระหว่าง **2.0 ถึง 23.5 นาที** รอบที่ไม่ใช้ skill ใช้ 4.4 นาที ([agentskillshub](https://agentskillshub.top/best/claude-video-skills/)) แต่ข้อสำคัญที่สุดซ่อนอยู่ในเงื่อนไข **การทดสอบนี้ไม่ได้ให้คะแนนความสวยเลย** แต่ละ skill รันแค่รอบเดียว และเว็บนี้ก็ขายพื้นที่โปรโมตด้วย หน้าตาตั้งต้นของรอบไม่ใช้ skill ถูกบรรยายว่า "น้ำทะเลสีเขียวอมฟ้าเข้ม คลื่น และตัวหนังสือขาวกลางจอ" ส่วน skill หลายตัวก็ยัดสไตล์ของตัวเองลงไป หน้าตาที่ได้จึงเป็นของ skill มากกว่าของคนสั่ง

คนที่ลงมือทำเองเล่าออกมาทางเดียวกัน Will Larson ทำคลิป Remotion สรุปสถิติบล็อกตัวเองได้ในไม่ถึง 10 นาทีต่อคลิป บอกว่า "ทำงานได้ดี" แต่จะเร็วกว่านี้อีกถ้ามี "ปลายทางที่ชัดกว่า" ตั้งแต่ต้น ([lethain.com](https://lethain.com/blog-recap-2026/)) กระทู้ HN "Opus 5.5 is good at explainer videos" ที่ได้ 433 คะแนนและ 223 คอมเมนต์ อ้างว่าคลิป explainer พวกนั้นใช้ค่า API ราว **$3–4 ต่อคลิป** บางคนได้งาน one-shot ที่ใช้ได้ แก้แค่เพลงที่ดังเกิน บางคนได้งานขัดเงาสวยแต่ **บัญญัติศัพท์ขึ้นมาเอง** อีกคนใช้เวลาราว 5 ชั่วโมงกับ Python ราว 4,500 บรรทัดเพื่อทำการ์ตูน XKCD ให้ขยับ แล้วก็ยังโดนติว่าหัวไม่บังพื้นหลัง ฟอนต์ชื่อเรื่องเพี้ยน และจังหวะเดินไม่เนียน ([HN 49836374](https://news.ycombinator.com/item?id=49836374)) คำติที่วนกลับมาในกระทู้เดียวกันคือโมเดลมักมองไม่เห็น layout ที่ผิดชัดๆ สไลด์เปลี่ยนเร็วจนอ่านไม่ทัน ดูดีแต่ไม่ค่อยให้ความรู้และพูดซ้ำจุดเดิม ภาษาแบบ LLM ต่อไอเดียไปเรื่อยๆ โดยไม่มีจังหวะของคนสอน และสไตล์เริ่มเดาได้จนมีคนบอกว่าคล้ายคลิปเปิดตัวของ Anthropic เอง ยังมีคนขอให้แชร์ session เต็มด้วย เพราะเดโมที่ขัดเงาแล้วอาจซ่อนการวนแก้นับไม่ถ้วนไว้

งานวิจัยก็ชี้ไปทางเดียวกัน TheoremExplainAgent (ข้อมูลปี 2025) สร้างคลิป Manim ยาว 5 นาทีขึ้นไปจากทฤษฎีบท STEM 240 เรื่อง agent ที่ใช้ o3-mini ทำสำเร็จ 93.8% แต่ **คลิปส่วนใหญ่ยังมีปัญหา layout เล็กๆ** ([arXiv 2502.19400](https://arxiv.org/abs/2502.19400)) งาน MoVer ที่ agentskillshub อ้างถึงพบว่า motion graphics จาก LLM ตรงโจทย์ตั้งแต่รอบแรกแค่ 58.8% และขึ้นเป็น 93.6% หลังวนตรวจแก้อัตโนมัติไม่เกิน 50 รอบ ([agentskillshub](https://agentskillshub.top/best/claude-video-skills/)) ลูปตรวจแก้ช่วยได้มากก็จริง แต่ลูปพวกนี้ตรวจแค่ว่า "ตรงสเปก" ไม่ได้ตรวจว่า "ดี" อีกเรื่องที่ควรรู้คือก่อน Opus 5.5 คนสร้างเครื่องมือ text-to-motion บน Remotion เคยบอกว่า Opus "ไม่ค่อยเก่งงานดีไซน์แม้จะมี skill" และบางครั้ง Gemini Flash ยังทำได้ดีกว่า ([HN 46855698](https://news.ycombinator.com/item?id=46855698)) คลื่นไวรัลรอบนี้จึงสะท้อนว่า Opus 5.5 ขยับขึ้นมาจริงในเรื่องรสนิยมภาพ แต่ยังไม่มีใครวัดว่าขึ้นมาแค่ไหน

แนวงานที่เหมาะก็ชัดตามมา งานที่ deterministic และขับด้วยข้อความหรือข้อมูลทำได้ดี ทั้ง kinetic typography, explainer, กราฟ, แผนที่, diagram และ demo สินค้า ส่วนงานที่ต้องการความสมจริง ตัวละครที่เคลื่อนไหวเป็นธรรมชาติ หรือบรรยากาศแบบหนัง ยังไปไม่ถึง ([HN 48939524](https://news.ycombinator.com/item?id=48939524)) ความล้มเหลวของวิดีโอจากโค้ดจึงหน้าตาต่างจาก generative video ไม่ได้ออกมาเป็นพิกเซลเพี้ยน แต่ออกมาเป็นภาพจืด องค์ประกอบชน จังหวะเร็ว และเนื้อหาตื้น ข้อหลังสุดมาจากบท ไม่ได้มาจาก renderer

## เสียง ภาพจริง และการดูงานตัวเอง ยังต้องยืมจากนอก Claude

Claude ไม่มีโมเดลเสียง โค้ดสังเคราะห์โทน เสียงบี๊บ SFX หรือดนตรีแบบ procedural ด้วย numpy ได้ แต่เสียงพากย์ต้องพึ่ง TTS ภายนอก ใน claude.ai ช่องนี้ตันเพราะ network allowlist เปิดให้แค่ package registry กับ GitHub ส่วน container ของ API ก็ไม่มีอินเทอร์เน็ตเลย ([Claude Docs: Code execution tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)) แม้ใน pipeline ที่ใช้งานจริง คนที่สร้างระบบให้ LLM เขียนบทแล้วส่งต่อให้ Remotion ใน Show HN ก็เลือกอัดเสียงตัวเองแทน เพราะ TTS ที่มากับระบบ "หุ่นยนต์เกินไป" ([HN 46457050](https://news.ycombinator.com/item?id=46457050)) ภาพสมจริง footage และ lip-sync ก็เหมือนกัน ต้องมาจาก HeyGen, Runway, Higgsfield หรือไฟล์ที่หามาเอง

อีกข้อที่คนมองข้ามคือ **Claude ดูวิดีโอไม่ได้และฟังเสียงไม่ได้** Claude อ่านได้แค่ภาพนิ่ง ส่ง GIF ไปก็เห็นแค่เฟรมแรก ([Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)) การ "ตรวจงานตัวเอง" ที่ Opus 5.5 ถูกชมจึงเป็นการดึงเฟรมตัวอย่างออกมาดูทีละภาพ claude.ai ส่งได้ไม่เกิน 20 ภาพต่อข้อความ และภาพ 1920×1080 หนึ่งเฟรมกินราว 2,691 token ([Claude Docs: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)) อะไรที่อยู่ระหว่างเฟรมที่สุ่มมา ทั้งความลื่นของการเคลื่อนไหว ภาพกะพริบ และเสียงตรงกับภาพหรือเปล่า ก็หลุดรอดได้หมด ส่วนเสียงต้องใช้เครื่องมือถอดเสียงหรือวัด loudness แล้วให้ Claude อ่านตัวเลขเอา

เทียบกับ generative video model แล้ว สองทางนี้เสริมกันมากกว่าแข่งกัน ราคาทางการของ Veo 3.1 ที่ 1080p พร้อมเสียงอยู่ที่ **$0.40 ต่อวินาที** สำหรับ Standard, $0.12 สำหรับ Fast และ $0.08 สำหรับ Lite และไม่มี free tier ([Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing)) สารคดี 10 นาทีด้วย Veo 3.1 Fast จึงตกราว **$72 ต่อเทค ก่อนนับรอบที่ต้องทำใหม่** ขณะที่ explainer จากโค้ดใช้ค่า API ราว $3–4 ต่อคลิปและไม่มีเพดานความยาว generative model ยังเขียนตัวหนังสือในเฟรมได้ไม่แน่นอน รีวิวภาษาอังกฤษยังขัดกันเอง ([vidguru](https://www.vidguru.ai/blog/veo-3.1-vs-kling-v2.6-comparison-benchmark.html)) และ **ยังไม่มีใครทดสอบภาษาไทยเลย** ตลาดนี้ก็ไม่นิ่ง หลายแหล่งรายงานว่า OpenAI ถอด Videos API และ Sora 2 ทุกรุ่นออกเมื่อ 24 ก.ย. 2026 โดยไม่มีรุ่นมาแทน ([techjacksolutions](https://techjacksolutions.com/ai-brief/openai-videos-api-sora-2-deprecated-september-2026/)) pipeline ที่ผูกกับ video API เจ้าเดียวจึงเปราะกว่า pipeline ที่เรนเดอร์จากโค้ดโอเพนซอร์สมาก

## สำหรับรู้ดีกว่า: pipeline เดิมมาถูกทางแล้ว ศัตรูตัวจริงคือหน้าตาที่ซ้ำ

MoneyPrinterV2 ทำสิ่งที่คลื่นไวรัลเพิ่งค้นพบมาตั้งแต่ก่อนหน้านั้นแล้ว Claude Code วางแผนและเขียนโค้ด renderer หลัก (`minimal_doc`) เป็น HTML player ที่ puppeteer จับภาพทีละเฟรมแบบล็อกเวลาแล้วส่งเข้า ffmpeg ซึ่งเป็นเทคนิคเดียวกับคลิปไวรัลอย่าง PDoomVideo โดยมี Python คุมขั้นตอนและรวมเสียง และมี Remotion เป็นทางเลือก เสียงพากย์มาจาก Gemini TTS ส่วนดนตรีประกอบกับ SFX แต่งด้วยโค้ด เทียบกับทุกช่องทางข้างบนแล้ว นี่คือรูปแบบเดียวที่ได้สารคดีมีเสียงพากย์ยาวหลายนาทีออกมาครบ claude.ai หรือ Cowork มาแทนไม่ได้ เพราะติดเพดานไฟล์ 30MB ไม่มี TTS ไม่รู้ว่ามีฟอนต์ไทยไหม และอาจ timeout กลางเรนเดอร์ยาว ของที่ควรหยิบจากกระแสนี้มีข้อเดียว Opus 5.5 ออกแบบกราฟิกเก่งขึ้น เลยน่าลองใช้เพิ่มความหลากหลายให้ชุดกราฟิก flat ของช่อง แต่ควรวัดจากตอนของช่องเอง ไม่ใช่จากคลิปไวรัล เรื่อง license ก็ไม่น่ากังวล renderer หลักไม่ได้ใช้ Remotion อยู่แล้ว และช่องที่ทำคนเดียวหรือทีมไม่เกิน 3 คนก็ใช้ Remotion ฟรีได้

ข้อความไทยทุกตัว ทั้งชื่อตอน ป้ายกำกับ และซับ ควรวาดด้วยโค้ดและฟอนต์จริงเสมอ ไม่ควรให้ generative model เขียนลงในเฟรม เพราะยังไม่มีหลักฐานว่าตัวไหนเขียนไทยได้ ฝั่ง renderer แบบโค้ดเองก็ยังไม่มีรายงานสาธารณะเรื่องสระลอย วรรณยุกต์ซ้อน หรือการตัดบรรทัดไทย ประวัติการผลิตของช่องเองจึงเป็นหลักฐานที่ดีที่สุดในเรื่องนี้

ความเสี่ยงที่ใหญ่กว่าฝีมือวาดภาพคือนโยบาย YouTube ตั้งแต่ 15 ก.ค. 2025 YPP เปลี่ยนชื่อกฎ "repetitious content" เป็น **"inauthentic content"** ห้ามคอนเทนต์ที่ผลิตจำนวนมาก ทั่วไป หรือซ้ำซาก และระบุชัดว่าไม่อนุญาตสไลด์โชว์ภาพ เนื้อเรื่องแบบ template หรือข้อความเลื่อนที่แทบไม่มีการเล่าเรื่อง รวมถึงคอนเทนต์ AI ที่ทำจาก template ทั่วไปจนดูเป็นการผลิตจำนวนมาก ส่วนที่อนุญาตคือ intro/outro ซ้ำกันได้ถ้าเนื้อหาหลักต่างกัน และซีรีส์ที่แต่ละตอนมีเรื่องหรือประเด็นของตัวเอง ([YouTube Help: YPP policies](https://support.google.com/youtube/answer/1311392)) ปี 2026 การบังคับใช้ก็หนักขึ้น Neal Mohan ประกาศให้การจัดการ "AI slop" เป็นงานหลักของปี ไม่กี่วันต่อมา ช่อง slop 16 จาก 100 อันดับแรกตามการศึกษาของ Kapwing ก็ถูกลบหรือล้างคลิป รวมผู้ติดตามราว 35 ล้าน ([TechTimes](https://www.techtimes.com/articles/320629/20260715/youtube-wiped-35m-subscribers-over-ai-slop-now-its-judging-your-taste.htm)) เปเปอร์ของ Google ยังอธิบายระบบ S-CTS ที่ปิดไปราว **50,000 กลุ่มบัญชี หรือราว 130,000 ช่องในหกเดือน** สัญญาณที่ใช้มีทั้งบทที่เป็น template ความถี่การอัปโหลดที่ไม่เหมือนมนุษย์ และสคริปต์ต้นทางร่วมกัน แม้ Google จะไม่ยืนยันว่าเอาระบบนี้ไปใช้จริงแล้ว ([Fstoppers](https://fstoppers.com/artificial-intelligence/how-google-machine-terminated-130000-ai-slop-youtube-channels-six-months-903645))

ตรงนี้แหละที่ pipeline แบบโค้ดเป็นดาบสองคม ความง่ายในการใช้ template เดิมไปเรื่อยๆ คือสัญญาณเดียวกับที่ระบบตรวจ slop มองหา ความเสี่ยงจึงไม่ได้อยู่ที่ "ใช้ AI" แต่อยู่ที่ "ดูเหมือนออกจากแม่พิมพ์เดียวกัน" ทั้ง layout ภาษาภาพ โครงเรื่อง และจังหวะอัปโหลด งานค้นหลักฐาน บทที่มีเส้นเรื่องของตัวเองทุกตอน และการรีวิวโดยคนแบบที่ Producer Mode ทำอยู่ ตรงกับฝั่งที่นโยบายอนุญาตอยู่แล้ว แต่ภาพก็ต้องต่างกันระหว่างตอนอย่างตั้งใจด้วย กราฟิก flat และแผนที่นับเป็นภาพที่เห็นชัดว่าไม่สมจริง จึงน่าจะไม่ต้องติดป้าย AI ขณะที่ B-roll สมจริงจาก Veo ที่จำลองเหตุการณ์ประวัติศาสตร์น่าจะต้องติด ([NBC News](https://www.nbcnews.com/tech/tech-news/youtube-says-will-require-creators-label-ai-content-rcna143937)) กฎข้อนี้ประกาศเมื่อปี 2024 และยังไม่ได้เช็กว่าปี 2026 เปลี่ยนไปหรือยัง ถ้าจะเติมชั้นบรรยากาศ ภาพเอกสารหรือ stock footage จึงปลอดภัยกว่า generative footage ส่วนงานที่คนต้องทำเองทุกตอน ทั้งเลือกมุมเรื่อง เช็กข้อเท็จจริงภาษาไทย ฟังเสียงพากย์กับดนตรี และดูคลิปที่ความเร็วจริงเพื่อจับข้อความไทยที่โดนตัด จังหวะ และ layout ก็ยังข้ามไม่ได้ ไม่มีแหล่งไหนแสดงให้เห็นว่าข้ามได้อย่างปลอดภัย

## สรุป

สิ่งที่ Opus 5.5 พิสูจน์ไม่ใช่ว่า Claude กลายเป็น video model แต่คือ Claude กลายเป็น motion designer ที่เขียนโค้ดเก่งพอจนการเรนเดอร์คลิปสั้นกลายเป็นเรื่องธรรมดา พอขั้นเรนเดอร์ถูกลงเหลือไม่กี่ดอลลาร์ ความต่างระหว่างช่องก็ย้ายไปอยู่ที่บท หลักฐาน เสียง และความหลากหลายของภาพ ทั้งการทดสอบ คอมเมนต์ใน HN และนโยบาย YouTube ชี้ตรงกันว่าส่วนนี้ยังต้องใช้คน ความย้อนแย้งที่ควรจำไว้คือ ยิ่งโค้ดทำให้ผลิตง่ายเท่าไหร่ งานก็ยิ่งเสี่ยงหน้าตาซ้ำจนเข้าข่าย template มากขึ้นเท่านั้น

วลี "ไม่ต้องต่ออะไร" เอาคำว่า "ไม่ต้องใช้ video model" มาปนกับ "ไม่ต้องตั้งค่าอะไร" สองคำถามที่แหล่งข้อมูลยังขัดกันอยู่ตอบได้ในห้านาที คือสั่ง `which ffmpeg` ใน sandbox ของ claude.ai กับเปิดเมนู Share ของ Claude Design ดูว่ามี MP4 หรือเปล่า แต่ไม่ว่าคำตอบจะออกมาทางไหน ข้อสรุปของช่องที่มี pipeline บนเครื่องอยู่แล้วก็ไม่เปลี่ยน
